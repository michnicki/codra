<objective>
Persist the `modelLineCap` value used at async submit time into the `file_reviews` table, so `pollReviewBatch` reconstructs the evidence haystack with the exact line cap the model saw — eliminating the race condition where a change in `transient_error_count` between submit and poll causes incorrect `not_in_hunk` evidence classification.

Purpose: Fix a bug in async batch evidence-haystack reconstruction. At submit (`submitReviewBatch`), `modelLineCap` is derived from `compactPrompt` (driven by `transient_error_count`). At poll (`pollReviewBatch`), it was re-derived from the *current* `compactPrompt`, which may differ if `transient_error_count` was incremented in between. When compact mode activates between submit and poll, the poll uses a shorter truncation boundary and evidence referencing lines in the truncated-away tail is incorrectly classified as `not_in_hunk`.

The revised design (incorporating cross-AI review feedback) retains `compactPrompt` at the poll call site so legacy in-flight rows with `model_line_cap=NULL` still get correct fallback — the two params coexist, with `modelLineCap` taking precedence when present.

Output: Migration 014 (`model_line_cap` column on `file_reviews`), exported `COMPACT_REVIEW_PROMPT_LINE_CAP`, widened `submitReviewBatch` return type, extended `pollReviewBatch` optional param, updated `upsertFileReview` with COALESCE preservation, updated call sites (submit AND poll), bulk mock return updates across test files, and three-layer test coverage with the unit test in a dedicated file to avoid `vi.mock` collision.

Decision coverage: D-01 through D-08 from phase CONTEXT.md are fully implemented by this plan. Cross-AI review consensus action items #1-#6 are incorporated.
</objective>
