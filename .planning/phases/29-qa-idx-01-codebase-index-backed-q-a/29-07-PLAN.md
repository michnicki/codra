<objective>
Wire retrieval into the read-only Q&A handler so a reviewer's question can reach relevant code outside the pull request diff, and prove that every failure mode degrades silently to today's behavior.

Purpose: this is the requirement's payoff — the Q&A answer widens from "pull request title, description and diff" to "plus relevant code from the rest of the repository". It is also the most dangerous place to get the failure handling wrong: the handler is documented read-only, and a reviewer waiting on an answer must never be blocked because an index is missing, building, or erroring.

Output: an additive read-only repository id lookup, the config-gated fail-open retrieval block in `src/server/core/qa.ts`, and the assertion battery in `test/qa.spec.ts` that pins fail-open, the byte-identical disabled path, variant selection, fence non-forgeability and the character cap.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reviewer question text → Postgres full-text query | Free-form user text becomes a query expression on a shared table |
| stored repository content → LLM system and user prompt | Committed source from files the pull request never touched now reaches the model |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-29-07-01 | Tampering | retrieved chunks reaching `buildQaPrompt` | high | mitigate | Each chunk passes through the imported `sanitizeUntrusted` and is fenced in the distinct retrieved-context sentinel pair, never merged into the diff fence; untrusted text never enters the system role. The forgery case asserts an exact end-marker count so a second boundary cannot appear. This is a genuinely wider surface than the diff — a payload committed long ago can fire on an unrelated pull request — which is why the variant system prompt also states the excerpts are untrusted data. |
| T-29-07-02 | Tampering | the reviewer's question reaching SQL | high | mitigate | `buildQueryTerms` restricts every term to lowercase alphanumerics and the expression travels as one bound parameter to `websearch_to_tsquery`; a null expression skips the query entirely. |
| T-29-07-03 | Information Disclosure | `retrieveCodeIndexChunks` call from the Q&A path | high | mitigate | The repository id is resolved by a provider-filtered read-only lookup and passed as the mandatory scope parameter, so a retrieval cannot span repositories. The provider filter also prevents the GitHub/Bitbucket owner-and-repo text collision from resolving the wrong tenant. |
