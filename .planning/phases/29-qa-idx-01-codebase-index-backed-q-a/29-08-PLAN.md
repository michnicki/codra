<objective>
Add the two dashboard endpoints that make the index usable: an explicit build trigger and a status read, both on the repository config route group, both provider-agnostic.

Purpose: the build trigger *is* the dashboard for this feature. Without these endpoints there is no way to create an index at all, and no way for an operator to see whether one exists, how fresh it is, or why a build failed.

Output: `POST /api/repos/:owner/:repo/code-index/build` and `GET /api/repos/:owner/:repo/code-index/status` in `src/server/routes/api/repos.ts`, plus a DB-backed route spec mirroring the existing on-demand-trigger spec.
