<objective>
Ship the operator surface: a repository-config panel that shows what the index covers and lets an operator build it, on both providers, plus the one manual Bitbucket step no automated test can cover.

Purpose: the build trigger is the dashboard. Without this panel the endpoints from the previous plan are unreachable in normal use, the feature cannot be verified by a human, and an operator has no way to tell whether an index exists, how fresh it is, whether it is partial, or why a build failed.

Output: two typed client calls, the panel component, its mount in the repository config surface, the add-Bitbucket webhook instruction, a browser spec, and one human verification of the end-to-end feature.
</objective>

## Flagged Assumption: the UI design contract was waived for this run

This phase has **no `29-UI-SPEC.md`** and no `29-SPEC.md`. The UI safety gate was consciously waived by
the developer (`--skip-ui`) on the planning run that produced these plans. Recorded here, in the plan
that owns the only dashboard surface in the phase, because it changes what an executor may assume:

- There is **no UI design contract** for this panel. Do not invent one, and do not treat any wording,
  spacing, colour or layout choice in this plan as design-reviewed.
- The substitute standard is **structural mimicry of a shipped sibling**:
  `src/client/components/features/repos/learned-rules-panel.tsx` is the authority for props shape, state
  shape, action sequence, heading classes, empty-state card, control labels and busy semantics. Where
  this plan is silent on a visual question, copy that file rather than deciding.
- The consequences are accepted rather than solved: no accessibility contract beyond the sibling's
  `aria-busy` and control labels, no defined responsive behavior, and no reviewed copy. The browser spec
  asserts *visible text and control state*, which catches "the state renders nothing" but not "the state
  renders badly".
- The visual result is therefore only checked by a human, at Task 3. That is the reason Task 3 is a
  blocking checkpoint rather than a nice-to-have.
