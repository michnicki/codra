## bitbucket-review-incomplete — Bitbucket PR reviews failed end-to-end (empty-commit 404, no model strategy, GitHub-flavored overview)
- **Date:** 2026-07-14
- **Error patterns:** BitbucketError, PUT /commit//reports/codra-review 404, empty commit segment, terminal check-run sweep 404 every 2 min, no inline comments posted, "No review model strategy is configured", ModelService.selectModel, review phase failed / job 'failed', finalize never runs, review-overview GitHub-flavored on Bitbucket, `<details>`/`<summary>`/`<br/>`/`<sub>` sanitized, `> [!NOTE]` rendered literally, visible `<!-- codra:job= -->` marker, "About Codra in GitHub"
- **Root cause:** Three independent gaps in the new Bitbucket provider path (all "review works on GitHub, broken on Bitbucket"):
  (A) `BitbucketAdapter.updateStatusCheck` posts Code Insights + build status to `this.job.headSha ?? ''`, but `headSha` was never populated for Bitbucket jobs — the mapped `PersistedReviewJob` publishes `commitSha` (not `headSha`) and the raw `JobRow` in the maintenance sweep has only the bytea `commit_sha`. Empty string → `/commit//reports/...` → 404, in BOTH the live finalize cosmetics call and the ~2-min maintenance sweep (which never records completion, so it retries forever).
  (B) The Bitbucket webhook route snapshotted `configSnapshot: defaultRepoConfig`, whose model section is empty (`{ main: null, fallbacks: [], size_overrides: [] }`). The GitHub route resolves the model via `loadRepoConfig` (global-strategy fallback); Bitbucket didn't. Empty model → `ModelService.selectModel` builds an empty chain → throws "No review model strategy is configured" → review phase fails before finalize → no comments, job 'failed'.
  (C) `formatReviewOverview`, the omitted-comments note, and the adapter's summary marker were not provider-aware, so GitHub-flavored HTML/copy (`<details>`, `<sub>`, `> [!NOTE]`, `<!-- -->` marker, "About Codra in GitHub", @mention/👍/draft copy) leaked onto Bitbucket, which sanitizes/renders it as junk.
- **Fix:** (A) `VcsService.forRepo` normalizes `headSha = job.headSha ?? job.commitSha` for the bitbucket branch (fixes live path); `completeTerminalCheckRuns` hex-decodes `commit_sha` → `headSha` (fixes the sweep). (B) The Bitbucket webhook route merges `getGlobalConfig` into the config snapshot — deliberately NOT `loadRepoConfig` (its `syncRepoConfig → getOrCreateRepository` side effect is GitHub-shaped and would create a spurious `vcs_provider='github'` repositories row). (C) `formatReviewOverview` + new `formatOmittedCommentsNote` take `{ provider }` (GitHub byte-identical, Bitbucket clean CommonMark); `review.ts` threads `vcs.name`; `BitbucketAdapter.submitReview` uses a clean footer dedup anchor (`codra-review · reviewed commit \`<12-hex>\``) instead of the `<!-- -->` marker + `<sub>`, matched by `content.raw` (Bitbucket preserves raw markdown, so dedup survives while rendering cleanly).
- **Files changed:** src/server/services/vcs.ts, src/server/core/job-recovery.ts, src/server/routes/webhook-bitbucket.ts, src/server/services/formatter.ts, src/server/core/review.ts, src/server/vcs/bitbucket.ts (+ tests: test/vcs-service.spec.ts, test/job-recovery-provider.spec.ts, test/bitbucket-webhook.spec.ts, test/formatter.spec.ts, test/bitbucket-adapter.spec.ts)
